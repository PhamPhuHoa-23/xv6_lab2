1. Which registers contain arguments to functions? For example, which register holds 13 in main's call to printf?

Answer: a0-a7 (8 registers). In main's call to printf, the value 13 is held in register a2.
Looking at line 24: "li a2,13" loads 13 into a2.
The first argument (format string) is in a0, second argument (f(8)+1 = 12) is in a1, third argument (13) is in a2.

2. Where is the call to function f in the assembly code for main? Where is the call to g? (Hint: the compiler may inline functions.)

Answer: There is no call to f or g in the assembly code for main. The compiler inlined both functions.
At line 26, we see "li a1,12" which directly loads the result of f(8)+1 into a1.
The compiler calculated f(8)+1 = g(8)+1 = (8+3)+1 = 12 at compile time.

3. At what address is the function printf located?

Answer: 0x630
Looking at line 30-34:
  30:	00000097          	auipc	ra,0x0
  34:	600080e7          	jalr	1536(ra) # 630 <printf>
The jalr instruction jumps to address 0x630.

4. What value is in the register ra just after the jalr to printf in main?

Answer: 0x38
The ra (return address) register contains the address of the instruction after jalr, which is the address of "li a0,0" at line 38.

5. Run the following code.
 unsigned int i = 0x00646c72;
 printf("H%x Wo%s", 57616, (char *) &i);
      
What is the output?

Answer: HE110 World
57616 in hex is 0xE110, so %x prints "E110".
0x00646c72 in little-endian is stored as: 72 6c 64 00
These bytes represent: 'r' 'l' 'd' '\0' which when read as string is "rld"
So %s prints "rld", giving "World".

The output depends on that fact that the RISC-V is little-endian. If the RISC-V were instead big-endian what would you set i to in order to yield the same output? Would you need to change 57616 to a different value?

Answer: i = 0x726c6400
In big-endian, bytes are stored in the order they appear, so to get the string "rld" we need the bytes in order: 72 6c 64 00.
57616 would not need to change because the integer-to-hex conversion is independent of endianness.

6. In the following code, what is going to be printed after 'y='? (note: the answer is not a specific value.) Why does this happen?
 printf("x=%d y=%d", 3);

Answer: A random value from register a2.
The printf function expects two arguments after the format string. We only provide one argument (3, which goes in a1).
The %d for y will read whatever value happens to be in register a2 at that time, which is undefined/garbage.
